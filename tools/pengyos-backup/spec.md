# pengyos-backup — spec

Backups for every PengyOS Server and Desktop: encrypted, deduplicated snapshots of
chosen directories to another machine, a disk or (later) a cloud bucket, taken
from btrfs read-only snapshots so they are consistent. The engine is **restic**
(`BR2_PACKAGE_RESTIC`, our recipe); this tool is the PengyOS layer over it: jobs
in files, a timer, snapshots of the `data` subvolumes, alerts, and output a GUI
or Pengy can read. Shipped in the Server overlay as `/usr/bin/pengyos-backup`
(one stdlib-only Python script), so both editions and both ISOs have it.

## Why restic, not rsync or rclone

rsync makes a mirror: a deleted or encrypted file is mirrored too and there is no
history. rclone moves files to clouds and is not a backup. restic keeps every run
as a snapshot, stores each chunk once (365 daily snapshots cost little more than
one), always encrypts, restores single files, and verifies itself (`check`). It
speaks local paths, SFTP, S3 (Backblaze B2 through its S3 API), and REST.

## Files

| Path | What |
|---|---|
| `/etc/pengyos/backup.toml` | the repository (`[repository] url`), retention (`[keep]`), integrity checks (`[check]`), alerting (`[alert]`) |
| `/etc/pengyos/backup.d/*.toml` | one job per file: `enabled`, `paths`, `exclude`, `exclude_if_present`, `max_file_size`, `snapshot` |
| `/etc/pengyos/backup/password` | the repository password, 0600 root, generated by `init`. **Lost password = lost backups.** |
| `/etc/pengyos/backup/env` | optional 0600 `KEY=VALUE` lines passed to restic (S3/B2 keys later) |
| `/etc/pengyos/backup/ssh/` | for `sftp:` repositories: the key `init` makes (`id_ed25519`) and `known_hosts` |
| `/var/lib/pengyos-backup/state.json` | last result per job (time, snapshot id, files, bytes added, error) |
| `/data/.pengyos-backup-snap/` | short-lived btrfs snapshots during a run; removed after |

A secret file that others can read is refused, as `pengyos-alert` does.

The image ships two jobs, both `enabled = false`:

- `system.toml`: `/data/etc/upper` (every change made to `/etc`: the overlay upper,
  usually a few MB) and `/var/lib` (service state).
- `home.toml`: `/home` and `/root`, minus caches, Trash, Flatpak app caches, Steam
  libraries, `node_modules`, and folders holding a `.nobackup` file.

## Commands

    pengyos-backup init --repo URL       set the repository, make the password (and an
                                         SSH key for sftp:), create the repository, print
                                         the recovery kit
    pengyos-backup kit                   print the recovery kit again (URL + password)
    pengyos-backup enable JOB | disable JOB   flip a job; the timer is on while any job is
    pengyos-backup run [JOB...] [--scheduled]  back up (all enabled jobs, or the named ones);
                                         --scheduled also applies [keep] and a due [check]
    pengyos-backup status [--json]       repository, jobs, last result and age of each
    pengyos-backup snapshots [JOB] [--json]
    pengyos-backup restore SNAPSHOT [--path P]... [--target DIR | --in-place]
    pengyos-backup mount DIR             browse every snapshot as folders (FUSE)
    pengyos-backup check [--read-data PCT]
    pengyos-backup restic ARGS...        restic itself, with this machine's repository

Exit codes: 0 ok; 1 a backup, restore or check failed; 2 misuse or missing setup.
`--root DIR` (tests) prefixes every system path; `--restic PATH` picks the binary.

## Behaviour

1. **One repository per machine**, every job in it, each snapshot tagged with the
   job name and the host name, so jobs share deduplication and `snapshots JOB`
   filters by tag.
2. **Consistent sources.** With `snapshot = true` (the default) every source path is
   mapped to the btrfs subvolume that holds it (walk up to the directory with inode
   256), each subvolume is snapshotted read-only into `/data/.pengyos-backup-snap/`,
   and restic runs in a private mount namespace (`unshare --mount --propagation
   private`) with each snapshot bind-mounted over its subvolume's path. restic so
   reads a frozen tree and records the real paths (`/home/...`), and nothing outside
   the namespace changes. Snapshots are deleted when the run ends, also on failure.
   A path not on btrfs is backed up live, with a warning. Nested subvolumes (for
   example `/var/log`) are not in their parent's snapshot and so not backed up.
3. **Retention** after a scheduled run: `restic forget --prune` per job tag with
   `[keep]` (default daily 7, weekly 4, monthly 12).
4. **Integrity**: a scheduled run whose last check is older than `[check] every_days`
   (default 30) runs `restic check --read-data-subset` (default 5%).
5. **Alerts**: a failed job sends `pengyos-alert send --priority high --key
   backup:JOB`; if its last success is older than `[alert] stale_days` (default 3)
   the alert is `urgent`. The service also has `OnFailure=pengyos-alert@`.
6. **Locks**: a run takes `/run/pengyos-backup.lock`; a second run waits for none
   and exits 2 with "already running".
7. Output for programs: `status --json` and `snapshots --json` are stable shapes
   (see README).

## Not in this version

The Desktop app, ISO "Restore from backup", the `[copy]` job (behoserver → B2), local
hourly snapshots, rest-server append-only repositories. An `sftp:` repository on
a normal account can be deleted by a compromised client: append-only comes with
rest-server.

## Acceptance

- Unit tests (fake restic, fake btrfs, sandbox root) cover job parsing, path →
  subvolume mapping, the namespace command line, retention and check scheduling,
  state, secrets' modes, alerts and every exit code; an integration test runs the
  real restic against a local repository when `restic` is on PATH.
- Proven on hardware: behothinkpad backs up `system` and `home` to
  `sftp:` behoserver from btrfs snapshots, a file is restored, `check` passes, and the
  host's mount table is unchanged after the run.
